## Скачать и установить

**Windows 10/11 x64:** нажмите кнопку выше, запустите установщик и откройте Optical CAD через меню «Пуск». Qt и библиотеки выполнения входят в пакет; компилятор и Qt SDK не нужны. Установка не требует прав администратора.

**macOS Apple Silicon:** скачайте архив кнопкой выше, распакуйте и откройте `optical_cad.app`. Пакеты пока без сертификата издателя и нотариализации Apple, поэтому система может показать предупреждение безопасности. Для встроенной Python-консоли отдельно нужен Python 3.

Кнопки начинают работать после первой успешной сборки и публикации. Все выпуски и контрольные суммы: [Releases](https://github.com/Roboric-sun/Optical-Cad-/releases).

## Ветки и выпуск программы

- `development` — разработка, весь исходный код и история проекта.
- `main` — код выпуска и автоматическая сборка установщика. Исходники здесь нужны для сборки.
- Для выпуска перенесите проверенные изменения из `development` в `main` через Pull Request. После успешных тестов Windows, macOS и расчётного ядра GitHub Actions создаст Release и обновит ссылки кнопок скачивания.
- Повторный выпуск можно запустить через Actions → Build and validate → Run workflow → `main`.


В этой ветке подготовлен кандидат 1.5.0; кнопки выше ведут на опубликованный выпуск. Пакеты текущей ветки доступны из её проверки CI.

## Версия 0.8.1 — поля по высоте

В **Последовательный режим → Поля зрения** выберите угол объекта, высоту объекта или параксиальную высоту изображения. X/Y показываются в градусах или миллиметрах. Расстояние объекта задаётся в том же редакторе: для высоты объекта оно должно быть больше нуля. При смене типа числа трактуются в новых единицах, поэтому задайте нужные координаты явно.

Параксиальная высота относится к гауссову сопряжению на первичной волне. Реальное пятно может отклоняться от неё; смена трассируемой волны и дефокус сохраняют исходное поле. Для этого типа требуются центрированные преломляющие схемы с определённым гауссовым сопряжением. Условие толщины по высоте реального луча поддерживает угол и высоту объекта; с параксиальным полем изображения оно пока отклоняется из-за зависимости от изменяемой схемы.

Новые типы требуют **формата 6** и Optical CAD 0.8.1. Угловые проекты сохраняются в подходящем прежнем формате 1–5. Импорт Geopter принимает Field.Type 0/1/2; прежние примеры сохранены. [Определения, ограничения и C++ пример](docs/FIELDS_RU.md).

## Версия 0.8 — редактор полей и виньетирование

**Последовательный режим → Поля зрения** открывает таблицу углов X/Y, весов и VUX/VLX/VUY/VLY. Коэффициент 0.4 сжимает соответствующую сторону зрачка до 60%; главный луч остаётся в центре. Поддержаны добавление, удаление и перестановка строк, пересчёт и undo/redo. При перемещении поля ссылки условий по лучу и функции качества сохраняют его идентичность.

Собственное ядро учитывает коэффициенты при прицеливании в STOP, расчётах пятен, ray fan, OPD и условий по лучу. PSF/MTF использует физическую сетку преобразованного зрачка. [Подробное объяснение и пример C++](docs/FIELDS_RU.md).

Теперь импортируется оригинальный `examples/geopter/dbgauss.json` с 11 поверхностями, внутренним STOP и ненулевым виньетированием. Исправлена оценка отсутствующих световых апертур внутренних поверхностей. Исходные апертуры не записаны в этом файле и оцениваются импортёром.

Ненулевые коэффициенты требуют **формата 5** и Optical CAD 0.8. Прежние шесть примеров и форматы 1–4 сохранены. Это первая часть этапа 0.8; дополнительные определения апертуры и расширенная асферика остаются следующими задачами [карты развития](docs/ROADMAP_RU.md).

## Версия 0.7 — условие высоты луча

В редакторе поверхностей откройте контекстное меню ячейки **толщины → Расчёт толщины… → Высота меридионального луча**. Выберите поле, волну, Y зрачка (−1…1) и знаковую высоту в мм на следующей поверхности или изображении. Высота 0 задаёт пересечение оси. В `marginal_focus.optcad` последний промежуток уже управляется краевым лучом на первичной волне.

Ядро вычисляет реальный луч с материалами проекта; поддерживает соосные схемы без зеркал, X поля=0 и STOP перед управляемым промежутком. Условие следует за изменением геометрии/материала/апертуры, работает с оптимизацией и undo/redo. Автофокус не перезаписывает связанную толщину до изображения. Недостижимая высота, перекрытый луч и цикл дают ошибку. Это фокус выбранного луча, который может отличаться от плоскости минимального RMS всего пятна.

Проекты с этим условием используют **формат 4** и требуют Optical CAD 0.7. Форматы 1/2/3 читаются; прежние типы проектов сохраняют свои версии. Для расчётов зависимостей по лучу из C++ передавайте реальный каталог: `applySolves(system, catalog)`, `resolvedSystem(system, catalog)`, `system.imageZ(catalog)`.

Добавлены [независимый эталон дублета](docs/BENCHMARKS_RU.md), исходный пример Geopter и [карта развития до Geopter и Zemax](docs/ROADMAP_RU.md). В выбранной версии Geopter JSON не сохраняет сами solves; неизвестные расширения с такими записями отклоняются, перенос отсутствующих условий не заявляется.

## Интерфейс по эталону

В версии 0.2 заменена временная оболочка: синяя строка документа, вкладки ленты в порядке приложений Г/Д, крупные и малые векторные значки, подписи групп снизу, навигатор на всю высоту и рабочие вкладки. В последовательном режиме редактор поверхностей расположен под схемой; строки объекта и изображения показываются как вычисляемые, доступные только для чтения. В непоследовательном режиме сцена и карта детектора со сводкой результатов видны одновременно. «Редактор объектов» открывает настоящие таблицы объектов и источников.

В навигаторе работает поиск; значок глаза у элемента скрывает его геометрию без изменения оптического расчёта. Куб в верхнем правом углу 3D-вида переключает стандартные виды. На панели сцены задаётся число отображаемых лучей; для увеличения числа сохранённых траекторий повторите трассировку. Цвет сегмента соответствует прямому лучу, отражению или рассеянию. Кнопка трассировки во время расчёта становится кнопкой остановки.

Недоступные функции оставлены на местах эталона и отображаются серыми с пояснением. Значки воссозданы средствами QPainter: оригинальные отдельные SVG/ICO не предоставлены. Поэтому побитовое или пиксельное совпадение всех значков не заявляется. Описание соответствия рисункам находится в [docs/UI_REFERENCE.md](docs/UI_REFERENCE.md).

Таблица поверхностей по умолчанию показывает компактные столбцы эталона. Двойной щелчок по покрытию открывает коэффициенты T/R, по наклону — все углы и децентрировки. Правой кнопкой мыши включается расширенное представление с отдельными координатами и коэффициентами асферики A4–A10.

В версии 0.4.1 исправлены выпадающие списки: выбранный пункт больше не скрывается белой полосой. Цвета текста и выделения заданы явно, в том числе при тёмной системной палитре. Каталог материалов прокручивается; выбор мышью, клавиатурой, отмена Esc и повторное открытие проверяются в GUI-тестах.

## Первый расчёт

В последовательном режиме измените радиусы, толщины, стекло и световые полудиаметры в нижней таблице. Радиус 0 означает плоскость; толщина последней поверхности задаёт расстояние до изображения. `STOP` назначает выбранную поверхность апертурной диафрагмой. «Параметры системы» задают входной зрачок, поля X/Y, длины волн, их веса, первичную волну, конечное расстояние объекта и дефокус. «Автофокус» минимизирует пятно первого поля на первичной волне.

Открывайте «Точечную диаграмму», «Разность хода», «Волновой фронт», «Функцию рассеяния» или «ЧКХ». Список полей над окнами выбирает поле анализа. Окна можно перемещать и отделять; таблицу и навигатор можно закреплять средствами Qt. Команды «Анализ → Одиночный луч», «Параксиальная трассировка» и «Описание системы» дают числовые отчёты. CSV выгружает данные активного графика с единицами в заголовке.

В непоследовательном режиме задайте тела в редакторе объектов, а положение, форму, спектральную линию, распределение и мощность источников — в редакторе источников. Запустите «Трассировку». Расчёт выполняется в отдельном потоке и останавливается кнопкой «Остановить». Детектор показывает мощность в ячейках и облучённость в Вт/мм²; это радиометрические величины, а не люксы. Число статистических лучей и число видимых траекторий задаются отдельно. Вращайте сцену мышью; масштабируйте колёсиком.

Изменение системы отменяет актуальность карты детектора. Отмена и повтор редактирования доступны через «Правка» и стандартные сочетания клавиш. Сохранение проекта выполняется атомарно.

## Учебное руководство и версия 0.6

[Как устроен Optical CAD: от калькулятора к программе на C++](docs/LEARNING_CPP_RU.md) объясняет используемые технологии, папки проекта, структуры, ссылки, единицы, трассировку, интерфейс, сохранение и тесты. В приложении: «Справка → Как устроена программа — изучаем C++» (F1), поиск по тексту и чтение без интернета. Учебный исходник — [examples/learning/first_lens.cpp](examples/learning/first_lens.cpp). Он считает линзу через настоящее ядро, печатает EFL/BFL, пятно до/после автофокуса, точки луча и результат связей. Сборка без Qt и упражнения описаны в руководстве.

В диалоге радиуса появился отдельный пункт **«Связь кривизны (1/R)»**. `c = множитель × c источника + смещение`, смещение задаётся в 1/мм. Для плоскости c=0; нулевая результирующая кривизна создаёт плоскость. Таблица сохраняет отображение радиуса в мм. Например, при R1=50, множителе −2 и смещении .01 получаем c2=−.03 и R2≈−33.333333 мм. Поддержаны существующие зависимости, оптимизация, undo/redo и сохранение. Проекты с этим новым правилом используют **формат 3** и требуют Optical CAD 0.6; форматы 1 и 2 по-прежнему читаются и записываются для прежних наборов функций.

## Новые функции версии 0.5

В редакторе поверхностей нажмите правой кнопкой на строке линзы и выберите «Связь радиуса…» или «Расчёт толщины…». В диалоге доступны:

- **Связь с другой поверхностью:** значение = множитель × значение источника + смещение. Радиус связывается с радиусом, толщина — с толщиной; единицы — мм. Например, задний радиус = −1 × передний. Радиус 0 сохраняет прежнее значение плоскости; это связь радиусов, а не кривизн.
- **Краевая толщина:** задаются толщина края и радиальная высота в пределах обеих апертур. Осевое расстояние рассчитывается по сагиттам соседних соосных поверхностей, включая конику и A4–A10. Наклон, децентрировка и зеркала в этом решении не поддерживаются.
- **Общая длина:** задаются начальная и конечная поверхности и расстояние между ними. Управляемая толщина должна лежать внутри интервала. При выборе изображения длина включает дефокус.

Связанный параметр отмечен значком цепочки и не редактируется вручную. Двойной щелчок по нему открывает диалог; «Фиксированное значение» снимает связь, сохраняя последнее рассчитанное число. Изменение источника обновляет зависимые значения и расчёты; работают отмена и повтор. Циклы и отрицательные толщины отклоняются. Вставка и перестановка сохраняют физические ссылки; удаление используемого источника и разделение пары с заданным краем требуют сначала снять связь.

Оптимизатор меняет независимые переменные и пересчитывает связи при каждой пробе. Зависимый радиус или толщина не могут одновременно быть переменной оптимизации. Если параметр уже включён в сохранённый план, сначала исключите его из таблицы переменных. Автофокус работает со связями радиусов и края, когда расстояние до изображения независимо; связи этого расстояния требуют ручного снятия перед автофокусом.

Пример `linked_singlet.optcad` связывает задний радиус с передним и сохраняет край 1 мм на высоте 12.5 мм. Измените передний радиус и наблюдайте пересчёт заднего радиуса и осевой толщины.

Проекты со связями сохраняются в **формате 2** и требуют Optical CAD 0.5 или новее. Версии 0.4.1 и ниже явно отклоняют их, чтобы не потерять зависимости. Проекты без связей сохраняют формат 1; все прежние примеры и проекты читаются новой версией.

## Новые функции версии 0.4

На вкладке «Оптимизация» откройте «Редактор функции качества». В таблице переменных задаются поверхность, параметр, минимум, максимум и начальный шаг. Доступны радиусы, толщины, коники, A4–A10 и дефокус. В таблице критериев задаются RMS пятна, EFL, BFL, положение изображения Z, центр X/Y и пропускание. Выбирайте отдельное поле или «Все поля»; задавайте цель, масштаб и вес. Геометрические цели и масштабы задаются в миллиметрах, пропускание — долей 0…1. «Рассчитать критерий» заполняет реальные значения и вклады без изменения системы.

«Оптимизация по настройкам» выполняет ограниченный координатный поиск в фоне. Критерий — безразмерный взвешенный RMS нормированных отклонений; для всех полей усредняются квадраты отклонений с весами полей. Поэтому улучшение общего критерия не гарантирует уменьшения каждого отдельного пятна. RMS и центры используют все спектральные линии и их веса; EFL/BFL — первичную волну. После расчёта открывается отчёт с параметрами и критериями до/после, а также историей проходов. «Остановить оптимизацию» сохраняет прежнюю систему. Редактирование во время расчёта делает его результат неактуальным; повторный запуск заблокирован до обработки завершения. Прежняя команда «Оптимизация радиусов» сохраняет свой критерий и поведение.

«Доля дошедших ≥» ограничивает геометрическое виньетирование на каждом поле; ноль отключает эту проверку. Она учитывает спектральные веса и не включает потери на покрытиях. Автофокус управляет последней толщиной и сбрасывает дефокус: при его включении исключите эти параметры из таблицы переменных. Цель автофокуса остаётся прежней — первое поле и первичная волна. Новые настройки сохраняются в `.optcad` и участвуют в отмене/повторе; вставка и перестановка поверхностей сохраняют ссылки переменных, удаление убирает связанные переменные. При удалении поля удаляются его критерии. Если таблица опустела, при следующей настройке предлагается новый стандартный набор.

В непоследовательном режиме на вкладке «Анализ» доступны «Профили и статистика» и «Сводка детектора в CSV». Для выбранного детектора показаны мощность, доля мощности источников, центр X/Y, RMS X/Y и радиуса, радиусы 50%/80% мощности и коэффициент вариации всей активной площади. Синие/зелёные профили интегрируют карту по другой координате; их единицы — Вт/мм, интеграл каждого профиля равен мощности детектора. «Выгрузка данных» сохраняет профили; отдельная команда сохраняет сводку.

Моменты и радиусы вычисляются по центрам ячеек: пятно внутри одной ячейки имеет нулевой **дискретный** RMS, а не физически нулевой размер. Повышайте разрешение детектора для оценки сходимости. CV учитывает и тёмные ячейки; при нулевой мощности моменты и CV показаны как отсутствующие, в CSV значения пустые. Остановленная трассировка отмечена как частичная. Доля мощности нормируется на реально запущенную мощность, а не на число попаданий.

Старые проекты остаются совместимы. Новые настройки оптимизации требуют версии 0.4 для восстановления; версия 0.3 их не использует. Подробнее: [изменения](docs/CHANGELOG.md), [проверки](docs/TESTING.md), [разрыв с возможностями Geopter](docs/GEOPTER_PARITY.md).

## Новые функции версии 0.3

«Аберрации» открывает два графика: тангенциальный T и сагиттальный S. Для поля вне оси T направлен вдоль радиального направления поля X/Y, S перпендикулярен ему; на оси используются Y и X. Оба графика относятся к главному лучу первичной длины волны и поэтому сохраняют поперечный хроматический сдвиг. Отсечённые лучи показаны пропусками. CSV содержит оба среза, длину волны в мкм, аберрацию в мкм и признаки допустимости каждого отсчёта.

В непоследовательном режиме кнопка «Призма» создаёт замкнутую равнобедренную треугольную призму. Треугольник расположен в локальной плоскости X/Z, основание на −Z, вершина на +Z; экструзия идёт вдоль Y. Полные размеры X/Y/Z задаются в редакторе объектов. Угол вершины равен `2 atan(X / (2 Z))`: например, X=20 мм и Z=17.320508 мм дают 60°. Все пять граней участвуют в столкновениях, преломлении и полном внутреннем отражении. Материал и поза редактируются обычными средствами. Размеры призмы ограничены диапазоном 0.00001–1000000 мм.

Откройте `examples/spectral_prism.optcad` и запустите трассировку: три источника с линиями 486.1, 587.6 и 656.3 нм показывают дисперсию N-BK7 на детекторе. Общая мощность 1 Вт, по 10 000 лучей на источник. Отображаемые траектории распределяются между источниками и чередуются; уменьшение числа видимых лучей сохраняет представительство спектральных линий. В CSV траекторий добавлены индекс источника, длина волны и категория входящего сегмента: 0 прямой, 1 отражённый, 2 рассеянный; у начальной точки категория пуста.

Старые проекты формата 1 открываются в версии 0.3. Новые проекты с типом объекта «Призма» требуют версии 0.3 или новее. Сведения об изменениях и контрольных результатах находятся в [docs/CHANGELOG.md](docs/CHANGELOG.md) и [docs/TESTING.md](docs/TESTING.md).

## Практические ограничения

PSF/MTF используют скалярное приближение Фраунгофера с входным зрачком и одной первичной длиной волны. Масштаб изображения определяется EFL центрированной системы; для наклонённой системы дифракционный расчёт выдаёт ошибку. Не моделируются векторная дифракция, поляризация и пространственная когерентность источника. Сетка FFT по умолчанию 64×64; пригодность для сильно аберрационных систем и сходимость по сетке ещё требуют исследования.

Каталожные показатели используются при опорных условиях производителя; температура, давление и поглощение внутри стекла не учитываются. Ручной nd/Vd восстанавливает приближённую дисперсию Коши. Оптимизация по настройкам выполняет локальный координатный поиск; глобальный оптимум не гарантируется. Пока нет DLS/Levenberg–Marquardt, произвольных пользовательских формул и допусков с компенсаторами. Решение по маргинальной высоте работает для описанных в разделе версии 0.7 соосных схем. Перекрытие лучей контролируется на выбранной дискретной сетке; коэффициенты поля задаются пользователем. Прежний оптимизатор радиусов по-прежнему выполняет автофокус и использует штраф за изменение EFL.

Непоследовательный режим поддерживает изолированные прозрачные тела, включая равнобедренные треугольные призмы. Произвольные многогранники, вложенные и пересекающиеся прозрачные объёмы, контакт разных стёкол, CAD-геометрия и смешанная трассировка пока не поддерживаются. 3D-вид является ортографической каркасной проекцией реальной сцены, а не CAD B-rep.

STEP/IGES, каталоги ОПАЛ, источники из измеренных файлов, объёмные/поверхностные детекторы и интеграция с САРУС отсутствуют. Python-консоль и API добавлены в 1.0.0-rc1. Матрица требований и дальнейшие этапы находятся в [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md). Промышленная точность пока не подтверждена сравнением с эталонной программой.

## Сборка

Требуются компилятор C++20, CMake ≥3.24 и Qt ≥6.5 с Widgets, Concurrent и Test. Ядро собирается без Qt и без сетевых загрузок.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/path/to/Qt
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix "$PWD/release"
```

На macOS можно использовать `zsh scripts/build_macos.sh`, при необходимости задав `QT_ROOT`. Для Windows x64 нужен комплект Qt для MSVC 2022 и установленный Visual Studio с инструментами C++:

```powershell
.\scripts\build_windows.ps1 -QtRoot 'C:\Qt\<version>\msvc2022_64'
```

Сборка macOS проверена на текущем ARM64 Mac с Qt 6.11.1. GitHub Actions при каждом push и pull request собирает приложение с Qt 6.11.1 на macOS и Qt 6.8.3 для MSVC 2022 на Windows, запускает физические и интерфейсные тесты и сохраняет готовые пакеты в артефактах. Отдельная Linux-сборка проверяет ядро без Qt. [Результаты автосборок и доступные пакеты](https://github.com/Roboric-sun/Optical-Cad-/actions/workflows/build.yml) видны после входа в GitHub с доступом к закрытому репозиторию.

Без интерфейса:

```sh
cmake --preset core
cmake --build --preset core
ctest --preset core
./build-core/optics_cli
./build-core/optics_cli --nonsequential
./build-core/optics_cli --optimize
```

## Структура

`include/optics` содержит публичные типы и интерфейсы; `src/core` — собственные расчёты без UI. `src/app` разделён при сборке на `optics_project` (форматы, импорт/экспорт и пакетные команды) и `optics_ui` (интерфейс). `optics_batch` использует проектный слой; `scripts/opticalcad.py` вызывает его из Python. `tests` проверяют независимые физические результаты, сохранение, редактирование, переключение режимов и реальные вычисления из интерфейса. Исходные рабочие материалы в `docs/source` хранятся только локально и исключены из Git; для сборки они не нужны. Источники числовых данных и сведения о зависимостях находятся в [docs/SOURCES.md](docs/SOURCES.md).
