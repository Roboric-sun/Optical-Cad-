# Поверхности и апертуры — Optical CAD 1.3.1

Это продолжение блока 1.3: цилиндрические и тороидальные поверхности, эллиптические/прямоугольные апертуры и круглый центральный экран. Свободные формы и аттестация волновых анализов новых профилей остаются отдельными задачами.

## Как попробовать

Откройте **Примеры…** и выберите:

- **cylindrical_lens.optcad** — линза с кривизной по X, плоским направлением Y и эллиптической световой апертурой. Фокусировка различается по направлениям.
- **toroidal_lens.optcad** — тороидальные грани с разными радиусами X/Y и прямоугольными масками. Раздельные силы видны в отчёте **Первый порядок 4×4**.
- **obscured_aperture.optcad** — обычная линза с центральным экраном; геометрическое пятно рассчитывается по прошедшим лучам.

Выделите строку поверхности и нажмите **Координаты → Профиль и апертура…** на ленте последовательного режима или одноимённую команду **Правки**. Выберите профиль и маску, задайте размеры и сохраните. Команда применяется одним действием undo/redo. Ошибки размеров показываются в редакторе. Точка и запятая принимаются общим числовым вводом.

В схеме **ZY / ZX / XY** переключает проекции. Серый пунктир — механическое продолжение, цветные линии — открытая часть профиля/граница апертуры, чёрный контур — центральный экран. Лучи отсекаются реальной маской в локальной системе поверхности; наличие CB и наклонов не переносит маску в ошибочную глобальную плоскость.

## Профили и параметры

| Профиль | Радиусы и область |
|---|---|
| Стандартный | Прежняя осесимметричная сфера/коника/асферика, без изменения её формул |
| Цилиндр X | Кривизна в сечении XZ, по Y профиль постоянен. Радиус и коника задают плоскую кривую; полиномиальные коэффициенты пока не поддержаны |
| Цилиндр Y | Кривизна в YZ, плоское направление X |
| Тороидальный | Круговая образующая в YZ с радиусом Ry, вращение вокруг прямой, параллельной Y, с радиусом Rx. В этом выпуске коника и асферические коэффициенты тора не поддержаны и явно отклоняются |

Нулевой радиус означает плоское направление. У тора Rx=0 получается цилиндр Y, Ry=0 — цилиндр X; Rx=Ry даёт сферу. Знаки радиусов сохраняются. Это тороидальная поверхность вращения, не биконическая поверхность. Определение соответствует геометрическому принципу, описанному в [официальной документации Ansys Toroidal](https://ansyshelp.ansys.com/public/Views/Secured/Zemax/v26102/en/OpticStudio_User_Guide/OpticStudio_Help/topics/Toroidal.html); поддерживаемое подмножество и формат принадлежат Optical CAD.

Для круговой образующей g(y)=y²/[Ry·(1+sqrt(1−y²/Ry²))], h=Rx−g. Центральная ветвь тора: z=g+x²/[h·(1+sqrt(1−x²/h²))]. При Rx=0 используется g без второго слагаемого. В точке вершины главные кривизны равны 1/Rx и 1/Ry. Нормаль вычисляется аналитически, включая зависимость h от Y.

Цилиндр пересекается через квадратное уравнение. Для тора вычисляются действительные корни уравнения четвёртой степени; производная разбивает его на монотонные интервалы и позволяет сохранить кратные корни касания. Каждый кандидат проверяется по центральной sag-ветви, затем выбирается ближайшее переднее пересечение. Неверная ветвь тора не считается оптической поверхностью. Коэффициенты масштабируются, но это вычисления с конечной точностью: крайне большие координаты и почти вырожденная геометрия требуют отдельной проверки сходимости.

## Маски и экран

Механический `semiDiameter` остаётся внешним кругом поверхности. Световая маска лежит внутри него:

- Круг использует этот полудиаметр.
- Эллипс задаётся полуосями X/Y.
- Прямоугольник — полуразмерами X/Y; его углы должны помещаться в механический круг.
- Центральное экранирование — круглый непрозрачный диск заданного радиуса, 0 отключает его.

Граница внешней маски и граница центрального экрана включаются в открытый просвет. Размеры должны оставлять ненулевой просвет и находиться в действительной области профиля. Для тора/цилиндра действительная область проверяется на механической границе; отдельное пересечение дополнительно проверяется по формулам sag. Автоматическая обрезка пересекающихся продолжений для новых профилей/масок отключена: рабочие апертуры задаются явно.

Проверяется первый геометрический контакт: луч не может пройти через экран и появиться на более позднем открытом корне той же поверхности. Заблокированный луч получает статус **Vignetted**, не преломляется и не попадает в пятно. Доля дошедших лучей и критерий пропускания учитывают маску; покрытие/Френель учитываются отдельно по прежним правилам. У оптимизации заданный минимум доли дошедших должен соответствовать открытой части апертуры. Это влияет на допустимость проекта, а не меняет нормировку входного света.

Для неосесимметричного профиля `pupilDiameter` означает физический диаметр STOP — так же явно, как для CB в 1.3. Для стандартных поверхностей только с новой маской прежнее определение EPD сохраняется. Объект поддерживает углы и конечные высоты; определения высот изображения требуют дальнейшего обобщения для неосесимметричных систем.

## Доступные анализы

Поддержаны трассировка, глобальные проекции, пятно, RMS, геометрическая MTF, первый порядок 4×4 и геометрические цели DLS. Scalar EFL/BFL для цилиндров/торов явно отклоняются: вместо одного фокусного расстояния используйте матрицу с отдельными X/Y. Например, одиночная граница воздух→n=1.5, Rx=100/Ry=50 мм имеет приведённые силы −0.005 и −0.01 мм⁻¹.

OPD, ray fan, осевые аберрации, PSF и дифракционная MTF для новых профилей/масок пока явно не аттестованы. Это особенно важно при центральном экране: прежний опорный луч перекрыт, и нельзя просто применить старую дифракционную формулу. Старые системы без новых профилей/масок сохраняют прежние волновые расчёты. Простые связи значений/кривизн сохраняются; специальные осевые решения для новых форм отклоняются.

Радиус, толщина и дефокус доступны геометрической оптимизации. Радиус вращения Rx редактируется вручную; отдельной переменной оптимизации Rx пока нет. Коэффициенты, которые выбранный профиль не поддерживает, не становятся скрытыми неработающими переменными.

## Файл, Python и обратная совместимость

Новые данные требуют **формата 10**, читаются форматы 1–9. Все прежние 16 примеров оставлены без изменений; добавлены три новых. CB и настройки DLS сохраняются вместе с новыми формами. Номер старого формата не может скрыть новые метаданные. Экспорт неподдержанного профиля/маски в Geopter отклоняется явно.

```python
from opticalcad import Project
p = Project.load("examples/toroidal_lens.optcad")
print(p.analyze(pupil_grid=9)["fields"])
print(p.first_order()["matrix"])
p.save("my_toroidal_lens.optcad")
```

В C++ `Surface.profile` выбирает форму, `radius` — радиус образующей, `rotationRadius` — второй радиус тора. `Surface.aperture` хранит маску. Реализация в `surface_shapes.cpp` отделяет геометрию, поиск пересечения и проверку просвета; интерфейс редактирует исходные параметры и вызывает то же ядро, что Python и batch.
