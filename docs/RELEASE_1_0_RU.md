## Определения апертуры и дифракции

`pupilDiameter` задаёт опорный диаметр пучка на первой вершинной плоскости. Физический радиус STOP равен `EPD/2 × |A_stop+B_stop/L|` для конечного объекта и `EPD/2 × |A_stop|` для бесконечного. Это сохранённое определение прежних версий. У Geopter при конечном объекте EPD относится к параксиальной плоскости входного зрачка; преобразование при обмене учитывает различие плоскостей.

- f/# в собственном редакторе: `EPD = |EFL| / f/#`.
- NA объекта: среда AIR, `EPD = 2 L tan(asin(NA))`; бесконечный объект запрещён.
- NA изображения: `EPD = 2 n_image tan(asin(NA/n_image)) / |C+D/L|`; при бесконечном объекте `D/L=0`. ABCD использует редуцированный угол; матрица и n относятся к первичной волне. Это параксиальная передача наклона, не точный нелинейный solve заданной апертуры.

Новая дифракция находит параксиальную плоскость выходного зрачка изображением STOP, затем пересекает с ней реальные лучи. Невязки волнового фронта вычисляются на опорной сфере через эту плоскость. Амплитудная квадратура учитывает якобиан перехода от опорной координаты зрачка к выходной; плотность входного потока равномерна в этой опорной координате. Это ограниченная скалярная модель, не универсальное физическое распространение поля. Все спектральные каналы вычисляются на общей сетке без интерполяции готовых растров; поперечный хроматизм сохраняется относительно первичного главного луча.

`sum(psf)=1` означает нормировку энергии **в расчётном окне**. Это не доказательство отсутствия энергии за окном. Размеры изображения: 32/64/128; сетка зрачка от `size/2+1` до 65. Проверяйте оба размера и сходимость метрик; сильные аберрации и обрезание окна требуют дополнительной проверки. Старый `diffraction()` оставлен для совместимости; новый C++ API — `polychromaticDiffraction()`.

## Архитектура и связи

```
optics_core (C++20, без Qt)
       ↑
optics_project (Qt Core: формат, Geopter, executeRequest)
       ↑                         ↑
optics_ui                    optics_batch
       ↑                         ↑
optical_cad / GUI-тесты       opticalcad.py / Python-консоль
```

GUI и его тесты теперь линкуют одну библиотеку `optics_ui`; проектный слой также собирается один раз. Qt не проник в физическое ядро. Python не содержит второй реализации оптики: передаёт запросы в `optics_batch`, который использует тот же загрузчик, каталог и функции ядра.

Проверенные цепочки: редактор → модель → solves → вычисления; перестановка → перенумерация ссылок; оптимизация → пересчёт зависимостей → финальное применение; serialize → deserialize → повторное вычисление; изменение → undo/redo; фоновая задача → проверка ревизии → принятие/отбрасывание результата; Python → локальная копия → валидация → одно действие undo.

При исключении или остановке Python исходный проект не меняется. При внешнем редактировании проекта результат консоли отклоняется. На Unix процесс запускается в отдельной сессии; при остановке уничтожается группа с дочерними расчётами. На Windows применяется Job Object. Прежний оптимизатор радиусов теперь тоже транзакционный и проверяет отмену. Диагностика дифракции отделена от OPD: ошибка одного анализа не скрывает другой.

## Формат и совместимость

Новые коэффициенты, модель Schott, реальные высоты и дополнительные переменные оптимизации требуют **формата 7**. Прежние проекты читаются; без новых данных сериализатор сохраняет минимально необходимый прежний формат. Подмена номера формата для новых полей/коэффициентов/связей отклоняется. Native-расширение Geopter хранит исходный проект; перед его использованием стандартная геометрия сверяется с повторным экспортом этого проекта. Устаревшее расширение вызывает ошибку, а не потерю внешних изменений.

## Проверка с работающим Geopter

Версия: `0edfbf52fcf0e3fc660e5ae33c354fd7a6be80d7`; JSON-зависимость: `199dea11b17c533721b26249e2dcaee6ca1d51d3`. Внешнее ядро собиралось отдельно в `/tmp`; его исходники и библиотека в Optical CAD не включены. Собственный адаптер и воспроизводимое сравнение: `scripts/benchmarks/`.

[Численные результаты](benchmarks/geopter-1.0-matched.json): 588 лучей на сетке 9×9 по пяти системам. Допуски заранее заданы в скрипте: EFL/BFL <1e-8 мм, каждая координата пересечения и OPL <1e-7 мм. Максимум ошибки пересечения ≈5.13e-9 мм; OPL ≈7.79e-9 мм, оба на асферике. На сферических схемах максимальные расхождения порядка 1e-13 мм.

Согласование включает одинаковые начальные координаты/направления и постоянный показатель каждого стекла, равный его значению в Optical CAD на первичной волне. Эталонный AGF явно задаёт нулевые термокоэффициенты и опорную температуру 25 °C. Такое сравнение проверяет трассировку, а не достоверность дисперсии/термооптики.

Отдельный запуск с родными настройками дал для Double Gauss расхождение BFL около 0.00234 мм и некоторых внутренних координат до 0.493 мм. Причины включают прицеливание только главного луча в Geopter против реального прицеливания каждого отсчёта STOP у нас, а также модели/условия стекла. **Эти результаты не замаскированы увеличенным допуском.** Полное равенство RMS, OPD и PSF/MTF двух программ при настройках по умолчанию не заявляется.

## Приёмка после rc1

Финальная локальная регрессия: 764 физических и 480 интерфейсных/файловых проверки плюс интеграция Python. Release и Debug с ASan/UBSan прошли все три группы CTest; ядро без Qt прошло отдельно. Проверка утечек отключена. [Отчёт проверок](TESTING.md) содержит команды/логи и ограничения платформенной приёмки.

1. Независимые OPD/PSF/MTF пройдены на семи схемах, трёх волнах и сетках 33/49/65: 365400 внешних трассировок. Включены конечный объект и выходная среда n=1.33; энергия окна оценена по Парсевалю. [Результаты и допуски](RELEASE_MATRIX_1_0_RU.md).
2. Исправлен экспорт последней плоскости: она сохраняет выходную среду, устраняя фиктивное преломление на AIR в Geopter. Добавлена регрессия.
3. Опубликована продуктовая матрица с явными границами скалярной дифракции, геометрического обмена, отдельного процесса Python и апертур.
4. Распакованный macOS ZIP прошёл реальные действия интерфейса: таблица, undo/redo, save/open, консоль, undo скрипта, отмена и завершение его потомка. В CI добавлен тот же сценарий для macOS и Windows: Qt SDK временно скрывается, PATH и профили изолированы. Создаётся полный Windows ZIP. **Подтверждение CI ещё требуется.**

Дальнейшие этапы 1.1+ (DLS, coordinate breaks, конфигурации, допуски) и 2.x не включены в эту работу. Непоследовательный режим сохранён и покрыт общей регрессией; вложенные прозрачные тела и смешанная трассировка остаются за текущей моделью.
