# Локальные системы координат — Optical CAD 1.3

Это первая часть блока 1.3 исходной карты: coordinate breaks, возврат координат, сложенная трассировка и дифференциальный первый порядок. Торические/цилиндрические поверхности, дополнительные формы апертур и аттестация волновых анализов вне оси остаются продолжением 1.3.x. Полный блок карты не объявляется завершённым.

## Как попробовать

Откройте **Примеры…**:

- **folded_mirror.optcad** — плоское зеркало 45° поворачивает свет с +Z на +Y. Следующая плоскость находится в Y=20 мм, изображение в Y=40 мм. Это геометрический пример, зеркало не фокусирует пучок.
- **coordinate_group.optcad** — линза смещена на Y=2 мм и наклонена на 3°; после неё координаты возвращаются к глобальной плоскости.
- **afocal_telescope.optcad** — два толстых элемента с подобранным промежутком; на опорной волне угловое увеличение −2. Это проверяемая параксиальная схема, не готовый широкоугольный телескоп.

На ленте последовательного режима есть группа **Координаты → Локальные системы…**. Та же команда доступна в меню **Правка**. Измените числа, нажмите **Проверить координаты**, затем **Сохранить**. Видны глобальные вершины и направления осей. Допустимы точка и запятая. Изменение участвует в undo/redo; **Сохранить как…** создаёт собственный `.optcad`.

В панели схемы команда **ZY / ZX / XY** меняет глобальную проекцию, обычное вписывание возвращает ZY. Пурпурная метка CB показывает преобразование, зелёные линии — локальную плоскость изображения. Пятна и геометрическая MTF используют локальные X/Y этой плоскости. Одиночный луч и `points_world_mm` API сохраняют реальные мировые точки.

## Что означает строка преобразования

В нашей таблице преобразование задаётся **перед существующей оптической поверхностью**, без добавления фиктивной преломляющей границы. Оно меняет номинальную систему данной и последующих поверхностей. Тип поверхности, стекло и обычный локальный наклон остаются самостоятельными параметрами. Преобразование не изгибает луч; изменение направления вызывают преломление или отражение.

| Режим | Действие |
|---|---|
| Без преобразования | Продолжить текущую номинальную систему |
| Относительное | Применить перенос/наклон в текущей системе; унаследовать результат далее |
| Возврат ориентации | Восстановить оси глобальной/выбранной предыдущей системы, сохранив текущую вершину; затем применить заданное смещение/наклон |
| Полный возврат | Восстановить вершину и оси выбранной системы; затем применить заданное смещение/наклон |

Ссылка относится к **номинальной системе перед обычным наклоном/децентрировкой выбранной поверхности**. Поэтому возврат к поверхности с обычным наклоном зеркала не означает возврат к её физической нормали. Глобальная система имеет O=(0,0,0) и обычные XYZ. Ссылаться можно только назад; удаление используемой опорной поверхности или перестановка, создающая ссылку вперёд, отклоняется. Остальные ссылки корректно перенумеровываются.

Пусть R — вращение Rz·Ry·Rx, t — введённый перенос, p — локальная точка:

- **Перенос → Наклон:** p_parent = R·p + t. Перенос измеряется в исходных осях.
- **Наклон → Перенос:** p_parent = R·(p + t). Перенос поворачивается вместе с новыми осями.

Например, перенос X=1 мм и Ry=90° даёт новую вершину (1,0,0) в первом случае и (0,0,−1) во втором. Толщина после поверхности всегда откладывается по новой номинальной +Z; отрицательная толщина не требуется для приведённого поворота зеркала. Обычный наклон поверхности влияет только на неё и не разворачивает ось следующих промежутков.

Принцип coordinate break и разделение геометрии/оптического действия описаны в [официальной статье Ansys](https://optics.ansys.com/hc/en-us/articles/42661737698451-How-to-tilt-and-decenter-a-sequential-optical-component); концепция возврата — в [Coordinate Return](https://optics.ansys.com/hc/en-us/articles/43071118475539-How-to-restore-coordinate-systems-using-the-Coordinate-Return). Конкретные правила и формат здесь принадлежат Optical CAD; совместимость со всеми соглашениями/файлами OpticStudio не заявляется.

## Зрачок, изображение и применимость

В системе с CB `pupilDiameter` задаёт **физический диаметр STOP**, а не автоматически восстановленный входной зрачок. Это явно записано в формате 9 (`pupilDefinition=physical-stop-diameter`) и подписано в параметрах. Прицеливание ищет точку в настоящей локальной плоскости STOP. Старые системы без CB сохраняют прежнее определение EPD.

Входная среда — воздух, направление входного объекта/углов задаётся в глобальной системе. Для бесконечного объекта стартовая плоскость автоматически выносится перед первой поверхностью, включая отрицательное глобальное Z. Поддержаны угловые поля и конечные высоты объекта; поля параксиальной/реальной высоты изображения для CB ещё не поддержаны.

Изображение наследует номинальную систему после последней поверхности: последний промежуток плюс дефокус откладываются по её локальной +Z. Глобальная точка изображения и локальные координаты — разные данные. В C++ `imageZ()` для CB явно отказывает; используйте `sequentialFrames(...).image`. Старое `vertices()` остаётся накопленной суммой скалярных промежутков, не массивом мировых Z для CB.

Доступны: глобальные схемы, реальная последовательная трассировка, пятно, RMS по полям, геометрическая MTF и первый порядок 4×4. OPD, ray fan, осевые аберрации, PSF/дифракционная MTF и автофокус для CB пока явно отклоняются. Геометрический RMS можно оптимизировать изменением последнего промежутка/дефокуса в DLS, без автофокуса. Поддержаны scalar pickup и curvature pickup; решения края, общей длины и высоты луча для CB ещё не аттестованы. Автоматическое обрезание пересечений соосных продолжений для CB отключено: рабочие апертуры нужно задать явно. Это не CSG и не обход пересекающихся объёмов.

## Первый порядок 4×4

Команда **Первый порядок 4×4** доступна на ленте координат и в меню **Анализ**. Матрица линеаризует (x,y,n·u,n·v) около входного осевого луча глобальной системы на z=0, где u/v — малые наклоны. На выходе используются локальная плоскость изображения и показатель выходной среды. Апертуры отключены, чтобы производная не подменялась виньетированием.

Вычисляются центральные разности с шагом 1e-5 мм для координат и 1e-5 для наклонов; C++/API допускает шаг 1e-7…1e-2. Афокальность означает норму нижнего левого блока <1e-8 мм⁻¹. Это диагностическая локальная линеаризация, не гарантированное единое EFL произвольной внеосевой системы. Если опорный луч не достигает приёмника, отчёт отказывает. Для преломляющей соосной системы матрица согласована с прежним ABCD после переноса до изображения; для зеркала проверены геометрическая чётность и углы; для телескопа — увеличение и исчезновение силы. Старый scalar `paraxial()` сохраняет прежний контракт и явно отказывает при CB/афокальности.

## Сохранение и Python

Новые координаты требуют **формата 9**. Версии 1–8 и все прежние 13 примеров остаются совместимы. Системы без CB сохраняют подходящий прежний номер. Подмена номера на 8 или отсутствие явного определения зрачка отклоняются. Неподдерживаемый экспорт Geopter явно отказывает, не удаляет CB.

```python
from opticalcad import Project
p = Project.load("examples/folded_mirror.optcad")
print(p.first_order())
print(p.analyze(pupil_grid=9)["fields"])
p.save("my_folded_system.optcad")
```

`first_order` возвращает matrix, afocal, output_index, chief_image_local_mm и chief_direction_local. Здесь поля с префиксом chief содержат указанный выше опорный осевой луч глобальной системы, а не отдельный луч, прицеленный через центр STOP. В `analyze` нет вымышленных EFL/BFL при неприменимости: есть paraxial_error и реальные геометрические данные. `trace_rays` дополнительно возвращает points_world_mm и image_local_mm; `points` для CB содержит настоящие локальные координаты поверхностей/изображения. Без CB прежний контракт `points` сохранён.

Для изучающего C++: `RigidFrame` хранит начало и три ортонормированных вектора осей. Сложение смещений само по себе недостаточно: сначала нужно выразить вектор в нужных осях. `coordinates.cpp` составляет преобразования, `sequential.cpp` пересекает поверхности и изображение в этих системах, а Qt-редактор только изменяет исходные параметры. Углы не извлекаются обратно из матрицы при каждом шаге, поэтому последовательность вращений не теряется.
