# Матрица приёмки Optical CAD 1.0

Версия ориентира: Geopter `0edfbf52fcf0e3fc660e5ae33c354fd7a6be80d7`; JSON `199dea11b17c533721b26249e2dcaee6ca1d51d3`. Геометрический набор: одиночная линза, дублет Kingslake, триплет Sasian, Double Gauss, асферическая линза. Дифракционный набор добавляет конечный объект и выходную среду n=1.33. Численные допуски заданы в скриптах до запуска; за пределами области модели приложение сообщает ограничение.

Это опубликованный состав рубежа из пункта 1 карты. «Сопоставим» означает совпадение перечисленных метрик при согласованных входных лучах и показателях преломления, а не совпадение всех настроек/алгоритмов Geopter или возможность запуска его Python-скриптов.

## Допуски и результаты независимого расчёта

Геометрия: EFL/BFL <1e-8 мм, каждая координата пересечения и OPL <1e-7 мм; 588 лучей на пяти системах. [Протокол](benchmarks/geopter-1.0-matched.json).

OPD/дифракция: 7 сценариев × 3 волны × 3 сетки, 365400 внешних трассировок, включая соседние отсчёты для якобиана. Параметры сценариев и [все результаты](benchmarks/diffraction-1.0.json) опубликованы. Допуски: OPD и RMS <1e-7 мм, масштаб пикселя <1e-7 мкм, сумма абсолютных ошибок PSF <1e-5, максимум ошибки MTF <1e-5. На полезной полосе до 70% отсечки MTF при переходе 49→65 отличается менее чем на 0.035; увеличение окна 32→64 также менее 0.035.

Фактические максимумы: OPD ≈4.81e-10 мм, сумма ошибок PSF ≈8.59e-7, MTF ≈3.87e-8; сходимость сетки ≈0.00353, окна ≈0.01487. Оценка энергии через равенство Парсеваля находится в диапазоне 0.98499…1.00016 от мощности зрачка при принятом допуске 0.95…1.03; небольшое превышение единицы отражает конечную квадратуру. Нормировка `sum(psf)=1` сама по себе не используется как доказательство сохранения всей энергии.

Внешний Geopter даёт пересечения, направления и OPL; Fresnel, корни опорной сферы, плотная комплексная квадратура и FFT выполняются отдельным NumPy-скриптом. C++ использует другую, разделяемую по осям реализацию. Никакая реализация Geopter не включена в приложение. Его встроенная PSF не объявляется эталоном: сравнивается явно заданная скалярная модель на внешних лучах.

## Установленные границы

- Дифракция: центрированные преломляющие схемы, поле ≤10°, конечный выходной зрачок перед реальным изображением, радиус/расстояние ≤0.25; без складок отображения. Проверенные значения EPD/полей указаны в протоколе. Набор конечных примеров не доказывает точность для любой схемы внутри этих геометрических ограничений.
- Тип апертуры переводится в диаметр, а не становится сохраняемым ограничением оптимизации. NA основана на параксиальной передаче углов. Формулы — в [отчёте](RELEASE_1_0_RU.md).
- Python запускается отдельным процессом; требуется Python 3.9+. Консоль находится внутри GUI, интерпретатор CPython не встраивается в адресное пространство Qt.
- Geopter ASP поддерживает A4…A22, ODD — A3…A12. Непредставимые коэффициенты, позы, покрытия, реальные высоты и пользовательская дисперсия отклоняются. Требуется согласованный каталог; в численном сравнении n каждого канала фиксируется по значению нашего каталога.
- Geopter при повторном сохранении удаляет native-расширение и собственные связи. Его изменённая стандартная геометрия с устаревшим расширением отклоняется; для импорта изменений расширение надо убрать. На уровне нативного проекта связи сохраняются.
- Mac-пакет подписан ad hoc, без нотариализации Apple; Windows-пакет переносимый, без MSI. Приёмка CI автоматизирована; ручное испытание на другом пользовательском компьютере не заявляется.
- DLS/LM, многоконфигурационность, допуски, coordinate breaks, смешанная трассировка и CAD-обмен остаются следующими этапами карты.

## Состояние платформенной приёмки

Локальная macOS ARM64 приёмка ZIP пройдена. Windows/macOS CI нового кода подготовлен; итоговый номер запуска и результаты будут записаны после его выполнения. До подтверждения обеих платформ выпуск остаётся подготовленным к приёмке.
