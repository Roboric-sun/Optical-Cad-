# Как устроен Optical CAD: от калькулятора к программе на C++

Это руководство для человека, который знает переменные, `if`, циклы и может написать калькулятор в терминале. Здесь разобран именно наш проект. Не нужно сразу понимать все формулы оптики или читать весь код.

Начните с разделов 1–5 и запустите учебный пример. Затем разберите его по разделам 6–9. Интерфейс Qt и фоновые задачи оставьте на второй проход. Для каждого шага ниже есть маленькое упражнение.

## 1. Что вы уже умеете и что добавится

Калькулятор обычно получает числа, выполняет действие и печатает ответ. Optical CAD делает то же самое с большим набором данных:

```text
Числа и выбор пользователя
            ↓
Описание линзы или осветителя в памяти
            ↓
Проверка данных → расчёт распространения света
            ↓
Числа, таблицы и рисунки на экране
```

В калькуляторе данные — два числа. Здесь это список поверхностей, материалов, длин волн и источников. Вместо одной операции выполняется множество небольших функций. Окно лишь удобный способ задавать данные и видеть ответ.

**Первая цель:** без окна рассчитать простую линзу. **Вторая:** найти эту же функцию в графическом приложении. **Третья:** внести небольшое изменение и проверить результат.

## 4. Сборка учебного примера без Qt

Для этого шага нужны компилятор с поддержкой C++20 и CMake не ниже 3.24. Qt не нужен. Если открывается уже собранное приложение, это ещё не означает, что на компьютере установлены инструменты разработки.

Нужны полные исходники из репозитория GitHub. ZIP с готовым приложением содержит руководство и примеры, но не весь исходный код ядра.

В терминале перейдите в папку исходного проекта. На текущем Mac это:

```sh

```

Затем выполните по очереди:


`-S .` указывает папку исходников. `-B build-learning` задаёт отдельную папку результатов. `-DOPTICS_BUILD_GUI=OFF` выключает окно и зависимость от Qt. Вторая команда компилирует; третья запускает физические проверки.

Запуск на macOS/Linux:

```sh

./build-learning/optics_learning 70
```

На Windows откройте терминал разработчика Visual Studio с установленными инструментами C++, перейдите в папку проекта и выполните те же команды CMake/CTest. Для генератора Visual Studio запуск обычно такой:

```powershell
.\build-learning\Release\optics_learning.exe
.\build-learning\Release\optics_learning.exe 70
```

Для генератора Ninja исполняемый файл находится прямо в `build-learning`. Число `70` — радиус передней поверхности в мм. Пример принимает значения от 25 до 2000. Десятичный разделитель — точка. Неверный ввод, например `abc` или `50xyz`, сообщает ошибку и возвращает код выхода 1.

Если `cmake` или компилятор не найден, сначала установите соответствующий инструмент. Инструкции сборки всего окна находятся в [README.md](../README.md); для начала достаточно этой консольной программы.

## 5. Как читать результат

Программа печатает шесть шагов:

1. Радиусы, осевую толщину и показатель преломления N-BK7.
2. EFL, BFL и диафрагменное число.
3. RMS пятна до и после автофокуса, координату изображения.
4. Координаты одного луча и оптическую длину пути.
5. Новый задний радиус из связи кривизн и толщину по заданному краю.
6. Пятно после повторного автофокуса уже изменённой линзы.

При радиусе 50 мм первая линза имеет R1=50, R2=−50 и толщину 5 мм. Параксиальный EFL около **49.212996 мм**. Это хороший первый ориентир: число проверяется также независимой формулой в физических тестах. После шага 5 задний радиус станет **−40 мм** — ниже объяснено почему. Вывод программы использует английские подписи, чтобы терминал Windows не зависел от кодовой страницы.

В учебном примере световой полудиаметр обеих поверхностей равен 10 мм, что совпадает с высотой заданного края. Геометрия проверяется до расчётов и после добавления связей: поверхности не должны пересекаться на всей своей апертуре.

**Упражнение:** запустите пример с 50 и 70. Сравните EFL и положение изображения. Зафиксируйте результаты перед изменением кода.

## 6. Структуры, списки и индексы

`struct` объединяет несколько переменных в один тип. Упрощённый пример:

```cpp
struct Surface {
    double radius = 0;
    double thickness = 5;
};
Surface front;
front.radius = 50;
```

Настоящий `Surface` также содержит материал, полудиаметр, конику и позу. `system.surfaces` — `std::vector<Surface>`, то есть список поверхностей, размер которого может меняться. `system.surfaces[0]` — первая поверхность, `[1]` — вторая. Отсчёт индексов в C++ начинается с нуля. В таблице программы физические поверхности обозначены 1 и 2; строки объекта и изображения добавляет интерфейс.

Материал поверхности задаёт **среду после неё** в последовательном расчёте. У передней поверхности демолинзы стоит N-BK7, у задней — AIR. Толщина — расстояние по оси до следующей вершины; у последней поверхности это расстояние до изображения. Дефокус добавляется отдельно.

| Запись C++ | Значение в этом проекте |
|---|---|
| `optics::Catalog` | Тип `Catalog` из пространства имён `optics` |
| `auto system = ...` | Компилятор выводит тип переменной из правой части |
| `const auto result = ...` | Полученный результат нельзя менять через эту переменную |
| `const auto& point` | Ссылка на существующую точку без копирования и изменения |
| `for (const auto& point : path.points)` | Пройти по каждой точке списка |
| `system.surfaces.size()` | Число элементов списка |
| `std::optional<SurfaceHit>` | Либо найденное пересечение, либо отсутствие результата |
| `enum class TraceStatus` | Именованные варианты результата трассировки |

Оператор `[]` не проверяет границы автоматически. Не обращайтесь к `[2]`, если в списке только два элемента. В проверках входных данных это особенно важно.

В `main(int argc, char** argv)` число `argc` включает имя программы, а `argv` содержит строки запуска. `argv[1]` — переданное вами число `70`; `std::stod` переводит строку в `double`. Пример проверяет, что строка прочитана целиком: `70abc` не принимается как 70. Лямбда `requireValid` с записью `[&]` обращается к уже созданным системе и каталогу по ссылке и вызывает проверку геометрии.

**Упражнение:** найдите определения `Surface`, `Ray` и `SequentialSystem` в `model.hpp`. Запишите своими словами назначение пяти полей каждого типа.

## 7. Единицы и векторная геометрия

Геометрия ядра задаётся в **мм**, длины волн — в **мкм**, углы полей и поз — в **градусах**, мощность — в **Вт**. Отсутствие единиц в типе `double` требует внимательности. Например, 550 нм нужно записывать как `.55` мкм. RMS из `spot` возвращается в мм; умножение на 1000 переводит его в мкм.

`Vec3` содержит `x`, `y`, `z`. Для положения это координаты, для направления — компоненты вектора. Направление луча нормируется: его длина равна 1. Умножив такое направление на расстояние, мы получим перемещение:

```cpp
optics::Vec3 start{0, 2, 0};
optics::Vec3 direction{0, 0, 1};
auto next = start + direction * 10;
// next = {0, 2, 10}
```

В `math.hpp` определены `operator+` и `operator*`, поэтому выражение выглядит как обычная арифметика. `dot` — скалярное произведение, `norm` — длина, `unit` — нормирование. Это первые математические функции, которые стоит разобрать самостоятельно.

Ось Z направлена вдоль исходной последовательной схемы. Знак радиуса задаёт направление центра кривизны. **Радиус 0 означает плоскость** по соглашению программы, а не сферу нулевого размера.

## 8. Что происходит с одним лучом

`pupilRay` создаёт луч для выбранного поля, длины волны и точки зрачка. Последние два аргумента — нормированные координаты зрачка. `(0,0)` — центр, `(0,.5)` — половина радиуса вдоль Y. Для круглого зрачка `px*px + py*py` должно быть не больше 1.

`trace` выполняет приблизительно такой порядок действий:

```text
Текущий луч
  → найти пересечение с очередной поверхностью
  → проверить световую апертуру
  → получить нормаль и показатели сред
  → преломить или отразить направление
  → добавить участок оптического пути
  → перейти к следующей поверхности
  → пересечь плоскость изображения
```

На границе действует закон Снеллиуса: `n1*sin(a1) = n2*sin(a2)`. В программе используется векторная форма в `refract`. Нормаль — направление, перпендикулярное поверхности в точке попадания. При полном внутреннем отражении преломлённого луча нет. Статус `TotalInternalReflection` в последовательной трассировке сообщает об этом; непоследовательная сцена может продолжить отражённый луч.

Оптическая длина пути OPL складывается из `показатель среды × геометрическая длина участка`. Она нужна волновым анализам; это не мощность и не просто расстояние от начала до конца.

В текущем API `path.opl` накоплена от начала луча **до последней пройденной поверхности**. Последняя точка `path.points` при `toImage=true` добавлена для изображения, но этот участок не добавляется в `opl`. Если нужен путь до плоскости изображения, прибавьте `path.index * (path.image - path.exitPoint).norm()` к OPL. Это соглашение важно при сравнении чисел и не меняет напечатанную траекторию.

Проверяйте `path.status` перед использованием результата. `Complete` означает, что трассировка завершена; `Miss`, `Vignetted`, `TotalInternalReflection` и `Invalid` описывают другие исходы. Учебный пример печатает точки только после проверки успеха.

**Упражнение:** измените `.5` в вызове `pupilRay` на `.8`. Сравните координаты и OPL. Затем верните исходное значение.

## 9. Пятно, автофокус и связи

Один луч не описывает качество линзы. `spot` берёт множество точек зрачка и длин волн, трассирует их и собирает точки изображения. Центр пятна и RMS учитывают веса и пропускание. RMS — среднеквадратичный размер отклонений от центра. Малый RMS для одной конфигурации не гарантирует хорошую систему на всех полях и волнах.

Вызов `spot(..., 9)` выбирает сетку 9×9; используются точки внутри круглого зрачка. В реальной работе более плотная сетка помогает проверить сходимость. Автофокус подбирает расстояние до изображения по геометрическому RMS первого поля на первичной волне. Печатный RMS учебного примера полихроматический, поэтому это не буквально тот же критерий.

Ссылки в объявлениях функций имеют значение:

```cpp
Spot spot(const SequentialSystem&, const Catalog&, Field, int grid);
double autofocus(SequentialSystem&, const Catalog&);
```

Первая функция получает систему через `const` ссылку и не изменяет её. Вторая получает изменяемую ссылку: новое положение изображения останется в `system`. Поэтому `auto candidate = system; autofocus(candidate, catalog);` позволяет попробовать фокус на копии.

В шаге 5 создаются два `ParameterSolve`. Первая связь задаёт:

```text
c1 = 1 / R1
c2 = -c1 - 0.005      (кривизна в 1/мм)
R2 = 1 / c2
```

При R1=50: c1=.02, c2=−.025, R2=−40 мм. Это отличается от связи радиусов `R2 = множитель*R1 + смещение`, где смещение измеряется в мм. Для плоскости кривизна равна 0; результат c2=0 снова записывается радиусом 0.

Вторая связь сохраняет край 1 мм на высоте 10 мм:

```text
осевая толщина = край + sag передней поверхности − sag задней
```

`sag` — высота поверхности относительно её вершины. Граф зависимостей сначала считает нужные радиусы, затем толщину. Цикл «A зависит от B, а B от A» отклоняется. При ошибке `applySolves` не записывает частично рассчитанные числа в исходную систему.

**Упражнение:** замените `curvature.offset = -.005` на `0`. При R1=50 получится R2=−50. Почему? Затем измените `edge.value` с 1 на 2: осевая толщина должна увеличиться ровно на 1 мм.

## 10. Как расчёт связан с кнопкой Qt

Консольный `main` выполняет действия и заканчивается. Оконный `main` создаёт `QApplication`, окно и запускает `app.exec()`. Этот цикл ждёт событий: нажатий кнопок, изменения таблицы, завершения задач.

Маленький пример сигнала и обработчика:

```cpp
connect(button, &QPushButton::clicked, this, [this] {
    recalculate();
});
```

Это означает: когда кнопка сообщит `clicked`, вызвать код внутри фигурных скобок. `[this] { ... }` — лямбда, небольшая функция, которая имеет доступ к текущему объекту окна. Qt сигнал не означает поток операционной системы: обычное нажатие здесь обрабатывается в потоке интерфейса.

В нашем `Window` редактирование обновляет модель проекта, создаёт запись истории, разрешает связи и вызывает пересчёт. `plots.cpp` рисует полученные координаты и массивы. Код рисования не вычисляет новый закон преломления. Нельзя менять физические параметры только в таблице и забывать обновить модель.

Вы встретите `new QLabel(..., parent)`: Qt обычно удаляет дочерние объекты вместе с родителем. В ядре используются значения, списки и автоматическое управление временем жизни. Для первых изменений вам не нужно вручную вводить `new/delete`.

**Упражнение:** найдите в `window.cpp` строку `undoAction`. Проследите, какая функция вызывается. Затем найдите `solveParameter` и её вызов из контекстного меню.

## 11. Непоследовательный режим и долгие задачи

В последовательной системе известен порядок поверхностей. В сцене следующий объект определяется ближайшим пересечением. Луч может попасть в линзу, отразиться от зеркала, уйти из сцены или достичь детектора. Расчёт использует случайную выборку лучей источников и учитывает мощность.

`rayCount` — сколько лучей считать; `displayRays` — сколько траекторий сохранить для рисунка. Изменение видимого числа не должно менять карту детектора. `seed` задаёт начальное состояние генератора. Разные стандартные библиотеки могут давать различающиеся реализации распределений; тесты учитывают это.

Ячейки детектора хранят мощность в Вт. Деление на площадь ячейки даёт облучённость в Вт/мм². Это не люксы: фотометрия потребовала бы дополнительных спектральных весов.

Если считать много лучей в обработчике кнопки, окно перестанет отвечать. Поэтому трассировка сцены и оптимизация работают в фоне на снимке данных. По завершении интерфейс проверяет актуальность проекта. Если пользователь уже изменил модель, старый результат нельзя применять. Это одна из причин, почему большая программа сложнее калькулятора.

Вложенные прозрачные объёмы, контакт разных стёкол и CAD-геометрия пока не поддержаны. Не начинайте обучение с добавления этих сложных механизмов.

## 12. Файл проекта, ошибки и отмена

`.optcad` — текст JSON с двумя частями: `sequential` и `nonsequential`. Материалы, настройки оптимизации, связи и рабочая область сохраняются вместе. Посмотреть копию файла можно текстовым редактором.

Формат 1 используется без связей, формат 2 — для прежних связей, формат 3 — если есть связь кривизн. Новая версия читает предыдущие форматы. Старая явно отклонит новую версию файла. Результаты анализов пересчитываются после загрузки.

`try` содержит действие, которое может не получиться; `catch` обрабатывает исключение:

```cpp
try {
    optics::applySolves(system);
} catch (const std::exception& error) {
    std::cerr << error.what() << '\n';
}
```

Неправильный материал, невозможная сагитта и цикл зависимостей должны стать понятной ошибкой. Программа не должна показывать старые вычисления как новые. При сохранении `QSaveFile` записывает временный файл и заменяет основной после успешного завершения. История отмены хранит снимки проекта; работающие фоновые задачи не входят в неё.

**Упражнение:** откройте копию `examples/linked_singlet.optcad`, найдите `solves`, `radius`, `thickness`. Сопоставьте их с двумя строками таблицы. Не меняйте основной рабочий файл вручную.

## 13. Как менять код и проверять себя

1. Сохраните исходный результат запуска и убедитесь, что тесты проходят.
2. Поменяйте одну небольшую вещь в учебном примере.
3. Соберите заново. Ошибки компиляции исправляйте начиная с первой.
4. Запустите пример и сравните результат с ожиданием.
5. Если меняли ядро или интерфейс, выполните соответствующие проверки.
6. Посмотрите `git diff`, чтобы убедиться, что изменили нужные строки.

Хорошая проверка имеет независимый ожидаемый результат. Например, при R=50 кривизна должна быть .02, а удвоение мощности источника в допустимой линейной модели удваивает мощность карты. Сравнение функции только с повторным вызовом той же функции не подтверждает правильность физики.

В `tests/core_tests.cpp` есть закон Снеллиуса, Френель и формула толстой линзы. В `tests/solve_tests.cpp` — связи и независимые геометрические числа. GUI-тесты нажимают кнопки, вводят данные, проверяют сохранение и отмену; они запускаются через Qt offscreen. Подробный отчёт находится в [TESTING.md](TESTING.md).

Для диагностики в IDE поставьте точку останова в `first_lens.cpp` перед `paraxial`. Просмотрите `system.surfaces[0]`, выполните «шаг с заходом» в функцию и «шаг с обходом» для вызова целиком. Следите за индексом поверхности, координатами и средой. Отладчик показывает причину неправильного числа гораздо лучше случайных правок.

## 15. Словарь и границы программы

**Апертура** — ограничение светового пучка. **Поле** — направление или положение рассматриваемой точки объекта; сейчас доступны угловые поля. **EFL** — эффективное фокусное расстояние. **BFL** — расстояние от последней вершины до параксиального заднего фокуса. **RMS** — среднеквадратичный размер пятна. **OPD** — разность оптического пути относительно опорной волны. **PSF** — распределение изображения точки в выбранной дифракционной модели. **MTF/ЧКХ** — передача контраста пространственных частот. **Pickup** — зависимость одного параметра от другого. **Функция качества** — число, которое оптимизатор старается уменьшить.

Текущая оптимизация — собственный локальный координатный поиск. Волновые анализы имеют перечисленные в README приближения. Совпадение названия анализа с Geopter не означает доказанного численного совпадения. Полное соответствие Geopter, промышленная точность и интеграция с САРУС ещё не заявляются; оставшиеся задачи записаны в [GEOPTER_PARITY.md](GEOPTER_PARITY.md).

Для дополнительного изучения используйте документацию уже применённых инструментов: [Qt Widgets](https://doc.qt.io/qt-6/qtwidgets-index.html), [CMake Tutorial](https://cmake.org/cmake/help/latest/guide/tutorial/index.html), [ресурсы для изучения C++ от Standard C++ Foundation](https://isocpp.org/get-started). Это отдельные материалы; наш минимальный учебный маршрут находится выше.

## Следующий опыт: фокус по одному лучу (версия 0.7)

Откройте `examples/marginal_focus.optcad`. Вторая поверхность имеет условие толщины: выбранный краевой луч должен попасть на Y=0 плоскости изображения. ПКМ по толщине → **Расчёт толщины…** показывает поле, волну и Y зрачка. Меняя радиус первой поверхности, наблюдайте пересчёт расстояния до изображения. Фокус одного луча может отличаться от автофокуса, который минимизирует RMS всего пятна.

В C++ условие создаётся так (в уже существующей программе с подключённым `optics/model.hpp`):

```cpp
optics::Catalog catalog;
auto system = optics::SequentialSystem::demo();
optics::ParameterSolve condition;
condition.parameter = optics::SolveParameter::Thickness;
condition.kind = optics::SolveKind::MarginalHeight;
condition.surface = 1;     // вторая физическая поверхность, индексы C++ с нуля
condition.reference = 2;   // следующий узел здесь — изображение
condition.value = 0;       // знаковая целевая высота Y, мм
condition.pupil = 1;       // верхний край зрачка; -1 — нижний
system.solves.push_back(condition);
optics::applySolves(system, catalog);
std::cout << system.imageZ(catalog) << '\n';
```

Для условия по лучу нужен настоящий каталог проекта: луч зависит от показателя преломления. Поэтому используем перегрузку функции с двумя аргументами. Старый вызов `applySolves(system)` подходит геометрическим связям, но новое условие без каталога даёт ошибку. Поле и волна задаются индексами; по умолчанию берётся поле 0 и текущая первичная волна. Явный `condition.wavelength = 0` выбирает первую волну независимо от первичной.

Новая логика находится в `src/core/solves.cpp`; тест `tests/marginal_tests.cpp` проверяет её по независимой формуле Снеллиуса, а `tests/marginal_gui_tests.cpp` — через редактор, файлы и отмену. [Численные эталоны](BENCHMARKS_RU.md) объясняют проверку дублета и границу OPL. [Карта развития](ROADMAP_RU.md) показывает следующие этапы.


## Поля и виньетирование (версия 0.8)

Кнопка **Поля зрения** теперь открывает отдельную таблицу. Добавлены четыре числа в структуру `Field`: `vux`, `vlx`, `vuy`, `vly`, по умолчанию все 0. Например, `system.fields[1].vuy = .4` уменьшает верхний радиальный размер используемого зрачка до 60%. Главный луч остаётся в центре. Код преобразования находится в `src/core/field.cpp`; его вызывает `pupilRay` перед прицеливанием в STOP.

Попробуйте `examples/vignetted_singlet.optcad`: изменяйте VUY выбранного поля и сравнивайте схему, пятно и MTF. В FFT пиксели зрачка заданы физическими координатами; обратное преобразование определяет, попадает ли пиксель в изменённый зрачок. Это позволяет уменьшенной апертуре расширять PSF. Пример исходного Geopter `examples/geopter/dbgauss.json` открывается через импорт JSON.

Редактор `src/app/field_editor.cpp` хранит номер-идентичность строки отдельно от её чисел: перемещение строки переносит ссылки условий и оптимизации на то же поле. Это полезный пример различия между объектом и его текущим индексом в векторе. [Подробное объяснение, ограничения и пример C++](FIELDS_RU.md).
