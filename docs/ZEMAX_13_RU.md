# Импорт схем из Zemax 13

Доступно начиная с Optical CAD **1.5.2**.

Реализовано чтение текстовых файлов `.ZMX` для ограниченного подмножества последовательных систем. Экспорт и управление запущенным Zemax не входят в этот интерфейс. Проверены два предоставленных пользователем файла с заголовком VERS 131125: `Afocal Riflescope.ZMX` и `Example 1, A singlet eyepiece.ZMX`. Сопоставлены сохранённые числовые параметры и проверена трассировка через физические элементы; сравнение анализов с запущенным Zemax пока не выполнено. Это импорт геометрии с ограничениями, а не полная совместимость всех расчётов.

## Использование

1. В Zemax сохраните схему в `.ZMX`. Архив `.ZAR` предварительно распакуйте средствами Zemax; двоичные `.ZOS` не поддерживаются.
2. В Optical CAD выберите **Файл → Импорт Zemax ZMX…** или откройте `.ZMX` обычной командой **Открыть**.
3. При неизвестном стекле сначала загрузите соответствующий каталог через **Импорт каталога**. Действующий импорт AGF поддерживает формулы Schott (1) и Sellmeier 1 (2). Название стекла должно совпадать точно; подмены стекла по одному показателю преломления нет.
4. Сохраните результат как `.optcad`. Исходный `.ZMX` не перезаписывается.

Командная строка:

```sh
optical_cad --import-zemax input.zmx --save-project imported.optcad
```

На macOS исполняемый файл находится в `optical_cad.app/Contents/MacOS/optical_cad`.

Python (встроенный каталог стекол):

```python
from opticalcad import Project

p = Project.import_zemax("input.zmx", executable="build/optics_batch")
p.save("imported.optcad")
report = p.analyze(pupil_grid=17)
print(report["efl_mm"])
```

Batch JSON: `{"operation":"import_zemax","data":"MODE SEQ\n..."}`. Поле `data` содержит текст ZMX; успешный ответ возвращает проект в `result.project`.

## Границы реализации

Поддерживаются центрированные преломляющие схемы в миллиметрах: плоскости, сферы, коники `STANDARD`, `EVENASPH` с A4…A16. Параметр 1 `EVENASPH` соответствует A2 и должен быть нулевым; параметры 2…8 соответствуют A4…A16. Коэффициенты более высоких порядков и иные типы поверхностей отклоняются.

`ENPD` задаёт диаметр входного зрачка; `FNUM` с флагом 0 переводится в диаметр через модуль параксиального EFL. При конечном объекте учитывается отличие плоскости входного зрачка от первого оптического вертекса. Поддерживаются FTYP 0 (углы), 1 (высота объекта), 2 (параксиальная высота изображения), только прямоугольная нормализация (второе поле FTYP равно 0). Число активных полей и волн берётся из FTYP; дополнительные слоты WAVM не добавляются к спектру. PWAV переводится из нумерации с единицы в индекс с нуля.

Объект и изображение исключаются из таблицы физических поверхностей; STOP хранится отдельно и может находиться на преломляющей поверхности. Расстояние до изображения — DISZ последней физической поверхности. INFINITY или объектный DISZ ≥ 1e10 трактуется как бесконечность. Виртуальные объекты, отрицательные внутренние толщины, изогнутые объект/изображение отклоняются. Отрицательный последний промежуток сохраняется как `defocus` при нулевой последней толщине: положение виртуального изображения сохранено, но обратная проекция лучей пока не реализована.

`FLOA` переводится из фиксированного радиуса STOP в диаметр зрачка через матрицу до диафрагмы и расстояние объекта, на первичной длине волны. В native сохраняется фиксированное численное значение, а не динамическое правило FLOA; пересчёт при редактировании и различия определения апертуры на других длинах волн требуют отдельной поддержки.

Нулевой DISZ объекта допускается для FTYP 1, когда первая поверхность — совпадающая с объектом плоская вспомогательная поверхность в воздухе, не STOP, без асферики, с положительным следующим промежутком. Эта поверхность удаляется, начало координат переносится к следующей; исходные номера сохраняются в `workspace.zemaxImport.sourceSurfaceNumbers`. Поля должны помещаться в апертуру удаляемой плоскости.

DIAM используется как фиксированный световой полудиаметр. Это зафиксированное значение из файла, а не автоматический пересчёт апертуры Zemax. CLAP/FLAP принимаются только при нулевом внутреннем радиусе, отсутствии смещения и совпадении внешнего радиуса с DIAM. Для физических поверхностей обязателен положительный DIAM. Трассировка Optical CAD может дополнительно ограничить эффективную апертуру на пересечении соседних линзовых поверхностей.

Неподдерживаемые записи вызывают ошибку: зеркала, координатные разрывы, неосесимметричные поверхности, ненулевые факторы виньетирования, покрытия, неизвестные стекла, модельные стекла, нестандартные апертуры, несколько конфигураций, специальные настройки среды. Для ENVD допускается только 20 °C / 1 атм. Solves/pickups отклоняются, за исключением `CHZH 0 0`: для него переносится сохранённая толщина DISZ как фиксированное число, с предупреждением об отсутствии живой связи. Функции качества и допуски не переносятся: распознаются комментарии BLNK, заголовок DMFS, операнды TRAC, пустые TOL/нулевые TOFF (в том числе составная запись `TOL TOFF ...`), стандартные MNUM/MOFF одной конфигурации и CSUM. CSUM распознаётся как служебная запись, но контрольная сумма Zemax не пересчитывается. Другие неизвестные записи отклоняются. Нельзя просто удалять отклонённые записи, если они влияют на оптическую схему.

Служебные записи отображения и анализов, включая RAIM, POPS, POLS, не переносятся. Переменные оптимизации в числовых хвостах CURV/DIAM не становятся переменными Optical CAD; импортируется сохранённая геометрия. Скалярная трассировка, прицеливание лучей, потери Френеля, определения пятна и OPD в Optical CAD могут отличаться от Zemax. Совпадение схемы не означает совпадения всех анализов.

Чтение: ASCII/UTF-8, UTF-16 LE/BE с BOM или без него. Другие кодировки следует предварительно преобразовать. Максимальный размер — 32 МБ; пределы текущей модели — 500 физических поверхностей, 50 полей, 20 активных длин волн.

## Проверка

`optics_zemax_tests` проверяет независимо рассчитанный EFL толстой линзы, трассировку луча, соответствие STOP и конечного зрачка, номера асферических коэффициентов, активные спектральные слоты, UTF-16, сериализацию и отклонение неподдерживаемых записей. Python integration проверяет реальный batch-процесс.

Пример `examples/zemax/singlet.zmx` составлен для тестирования импортера и не является файлом, сохранённым или проверенным Zemax 13.

`optics_zemax_files` использует неизменённые пользовательские файлы из `tests/data/zemax`. Для прицела сверены 17 поверхностей и STOP №8; для окуляра сверены поверхности №2–4 и STOP №4, после исключения совпадающей с объектом вспомогательной поверхности №1. Проверены все радиусы, промежутки, материалы, полудиаметры, активные поля/волны, матрица FLOA, сохранение и повторное открытие `.optcad`. Тесты интерфейса проверяют загрузку обеих схем, отрисовку геометрии, запуск анализов и видимое предупреждение о ручном тестировании.

Афокальный флаг FTYP и виртуальное изображение сохраняются в `workspace.zemaxImport`. В сборке для ручного тестирования искусственная блокировка вычислений по этим флагам снята: GUI и batch запускают существующие алгоритмы пятна, волнового фронта, PSF/MTF, автофокуса и оптимизации. Это не добавляет отсутствующую физическую модель. Проверки корректности входных данных и фактические ошибки алгоритмов сохраняются.

На графиках отображается жёлтый баннер «Ручное тестирование Zemax — результаты могут быть неточными»; полное предупреждение находится в строке состояния. Для успешных batch-операций и JSON-отчётов возвращаются `experimental: true`, `analysis_warning` и `import_warnings`. Ошибочный batch-ответ содержит исходную ошибку алгоритма, `experimental: true` и `analysis_warning`. В Python исключение `OpticalCADError` сохраняет исходный текст ошибки и атрибут `analysis_warning`. Это действует также при открытии ранее сохранённого `.optcad` с метаданными Zemax. Проекты без метаданных импорта работают в прежнем режиме.

`analyze` возвращает рассчитанные поля, включая `spot_status: no_power` и `rms_mm: null`, если лучи не достигают изображения. `wavefront`/`diffraction`/`autofocus`/`optimize` запускаются без запрета из-за происхождения файла, но могут завершиться собственными ошибками. Параксиальный EFL прицела описывает остаточную силу сохранённой схемы, а не угловое увеличение Zemax; пятно в мм на выходной плоскости не является угловым пятном. При виртуальном изображении ядро по-прежнему не выполняет обратную проекцию, поэтому возможны отсутствие мощности на изображении и ошибки волнового расчёта. Нулевые и отсутствующие результаты нельзя считать подтверждением качества системы.

Для сравнения можно использовать Python:

```python
p = Project.import_zemax("Afocal Riflescope.ZMX", executable="build/optics_batch")
report = p.report("riflescope-test.json", pupil_grid=17)
print(report["analysis_warning"])
for field in report["fields"]:
    print(field["spot_status"], field["rms_mm"])
```

`optics_zemax_files` сравнивает результаты и ошибки операций для импортированной схемы и той же геометрии без метаданных Zemax: предупреждение не должно подменять или пропускать вычисления. Для обоих файлов формируется `verification.json` с параметрами, результатами полей и ошибками операций:

```sh
python3 tests/zemax_file_tests.py build/optics_batch . artifacts/zemax13-manual-test
```

Ручная проверка: импортировать оба `.ZMX` либо открыть прежние `.optcad`, убедиться в наличии жёлтого баннера, открыть вкладки пятна, OPD, PSF и MTF, затем сохранить JSON-отчёт и сравнить его с Zemax при одинаковых полях, длинах волн, апертурах и сетках. Первое сравнение выполнять на копиях проектов: автофокус и оптимизация изменяют геометрию.

Предупреждения о фиксированной CHZH, преобразовании FLOA и исключении вспомогательной поверхности сохраняются вместе с проектом в `workspace.zemaxImport.warnings`.

Для приёмки на реальной системе: сохраните файл из Zemax 13, импортируйте его и сравните таблицу поверхностей, стекла, STOP, поля, длины волн, EFL/BFL, координаты нескольких лучей и RMS при одинаковых сетках, весах и правилах учёта пропускания.
